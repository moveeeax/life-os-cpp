`PUT /api/v1/food/goals` with a body that is valid JSON but not an object (`[]`, `5`) answers 400 `invalid_body` instead of storing an all-default profile with 200. The same rule now covers every Food body outside the parse routes, every Workout body, `PUT /api/v1/fitness/goals` and `POST /api/v1/jobs`: an array or a scalar answers 400 `invalid_body` ("the body must be a JSON object"). Before, these routes answered such a body with a field error (400 `validation_failed`, `invalid_steps`, `invalid_date`, `invalid_add_ml`, `invalid_ml` or `invalid_code`), and the Food plan, plan template and batch entry routes gave `invalid_body` with their own message.
