CI frees runner disk before the vcpkg build, starts sccache with a longer timeout (and compiles without it if it still does not start) and no longer fails on a cache export error, so a full disk or a slow cache does not hold up a release tag. The agents' quota reads `Mi` and `Gi` (`2Gi` used to become `0Mi` and refuse every agent pod) and leaves room for the image pre-puller, and `scripts/check-helm-render.sh` now renders the ani worker release and checks its token, quota, network policy, job types and that the pre-puller warms the image the pods run. The OpenAI key of Ani's agent no longer reaches the API pod: the API takes the Secret `life-os-ani-agent` key by key, and only the ani worker needs the key and the proxy URL. New API tests cover who may read and send in the owner's Telegram and who may see, delete, confirm or cancel another user's Ani turns and proposals. The spec describes the `POST /api/v1/ani/facts` and calendar event `PATCH` answers, and adding a calendar event answers 502 instead of an empty event when Google's reply cannot be read. Two tests no longer fail around midnight UTC, the compose worker pulls `leetcode_sync`, and the runbook covers the ani worker in rollbacks and secret rotation, the Telegram and calendar keys and a TLS check of the Telegram gateway from inside a pod.
