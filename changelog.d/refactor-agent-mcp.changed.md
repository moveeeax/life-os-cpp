Ani's agent and MCP stack reorganised without a change in behaviour: the tool helpers live in `agent/ToolArgs.hpp` and the call to the site's API in `agent/SiteApi`; the write tools are one table in `agent/Actions.cpp` (is_write, propose and the MCP schemas are lookups in it) with the proposals split by domain into `agent/{Task,Ledger,Telegram,Calendar}Actions.cpp`; a turn's toolset is built from a family list in `agent/Toolset.cpp` and the webhook event job moved to `agent/HookEvents.cpp`; `Hook::parse` is a per-type table, and the MCP command tools take their limits and dispatch from the Hook constants (a new unit test pins the two together); reminders and the message checks are shared by the API and the MCP; the Ani controllers use `with_repo_errors` and one `Utils::base_url()`.
