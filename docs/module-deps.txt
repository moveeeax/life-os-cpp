# module-deps.txt — the allowed include edges between src/ directories.
#
# Read by scripts/check-module-deps.sh: every `#include "dir/File.hpp"` in
# src/ produces a directory-level edge `<includer-dir> -> <dir>`, and any
# edge not listed here fails CI. Same-directory edges (api -> api) are
# always allowed and not listed. Files at the src/ top level (main.cpp,
# worker_main.cpp, the generated version.hpp) are the pseudo-directory
# `root`.
#
# Layering intent (violations of these three are rejected even if someone
# adds the edge below — the gate hard-codes them):
#   * utils/ is the bottom: it may include nothing outside utils/.
#   * core/Core.hpp is the composition root: only the binary entry points
#     (root), api/HealthController.hpp and its own body file core/Core.cpp
#     may include it. Everything else
#     that needs a module switch or the shutdown flag includes the tiny
#     utils/Modules.hpp instead (it keeps the Core:: namespace).
#   * jobs/ is a leaf of the module graph: the queue, the dispatcher, the
#     outbox and the queue's own built-ins. A module's job handlers live in
#     src/<module>/jobs/ and depend on jobs/, never the reverse; core/ (the
#     composition root) registers them all (core/JobHandlers.cpp).
#   * A module's part of the Now digest lives in src/<module>/now/ and is
#     the only thing api/TodayController.cpp reads of that module.
#   * webhooks must not include email (that edge closed the
#     email <-> jobs <-> webhooks cycle; the shared curl bootstrap lives in
#     utils/CurlInit.hpp).
#
# Adding a genuinely new dependency? Add the edge here in the same PR and
# say why in the PR description. Keep this file sorted.
#
# Nested directories are their own nodes (the gate keeps the full directory
# of an include): fitness/xiaomi, fitness/sync, repositories/fitness,
# domain/fitness are edges in their own right, not folded into their parent.
